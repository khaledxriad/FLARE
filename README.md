# FLARE: Flooding for Leakage-Resilient Lattice Encryption

Code and data accompanying the paper **"FLARE: Flooding for Leakage-Resilient Lattice Encryption"**
(FLARE = FLooding with Renyi-Exponent accounting), submitted to *PeerJ Computer Science*.

- Author: Khaled Riad (corresponding author), kriad@kfu.edu.sa
- Affiliation: Computer Science Department, College of Computer Sciences & Information Technology,
  King Faisal University, Al-Ahsa, 31982, Saudi Arabia
- Repository: https://github.com/khaledxriad/FLARE
- Archive (Zenodo): https://doi.org/10.5281/zenodo.24218048

## Description

Decoding in lattice-based encryption exposes a noise term that is linear in the secret key. If an
adversary observes many decodings (for example through a side channel), the key can be recovered.
FLARE adds fresh Gaussian noise ("flooding") to the exposed value and accounts for the remaining
security with the Renyi divergence. This repository contains the reference code that computes the
paper's closed-form quantities (noise deviation, modulus size, number of safe decodings), runs the
experiments reported in the paper, and the data files behind every table and chart.

The experiments use toy sizes and plain Python/NumPy. They validate the noise model, the
correctness bound and the leakage bounds. They are not a constant-time or production
implementation and do not measure physical side-channel traces.

## Dataset information

All data are generated by the scripts and stored as comma-separated values in `data/`. There is no
external or personal data.

| File | Content | Used for |
|---|---|---|
| `table_params.csv` | Six parameter sets: analytic and Monte Carlo exposure variance, norm bound, number of bound violations | Validation of the noise model |
| `table_design.csv` | Required flooding deviation, maximum number of decodings, required modulus bits, feasibility | Flooding design and feasibility |
| `chart_sigma_vs_lambda.csv` | log2 of required sigma versus target security, four methods | Baseline comparison |
| `chart_modulus_vs_N.csv` | Required modulus bits versus log2 of leaked decodings, four methods | Baseline comparison |
| `chart_budget.csv` | log2 of the maximum number of decodings versus log2 sigma | Leakage budget |
| `chart_alpha.csv` | Remaining security bits versus the Renyi order alpha | Choice of the Renyi order |
| `chart_attack.csv` | Number of decodings needed by a passive least-squares attack versus sigma, with the information floor | Validation against an attack |
| `chart_correct.csv` | Measured decryption-failure and bit-error rates versus sigma | Correctness under flooding |
| `chart_timing.csv` | Decoding time with and without flooding, three random sources | Cost of flooding |

Column names are given in the first line of each file. Units: sigma is the standard deviation of the
flooding noise in integer units of the modulus; times are in microseconds.

## Code information

| Script | Purpose |
|---|---|
| `code/floodlib.py` | Shared library: parameter sets, exposure variance, Renyi and KL formulas, the square-root law, closed forms for sigma and the maximum number of decodings, baseline formulas |
| `code/exp1_budget.py` | Parameter table, Monte Carlo exposure statistics, design table, budget and baseline curves |
| `code/exp2_attack.py` | Passive least-squares key-recovery attack on a toy ring-LWE instance (n = 64) |
| `code/exp3_correct.py` | End-to-end flooded decryption and correctness measurement |
| `code/exp4_timing.py` | Timing of flooding with three random sources |
| `code/check_results.py` | Recomputes the headline claims from the CSV files and prints PASS/FAIL |
| `code/plot_results.py` | Draws PNG plots from the CSV files into `plots/` |
| `code/run_all.sh` | Runs everything in order |

## Requirements

- Python 3.9 or newer
- numpy, scipy, matplotlib (see `requirements.txt`)
- No network access, GPU or special hardware is needed.

## Usage instructions

```
git clone https://github.com/khaledxriad/FLARE.git
cd FLARE
pip install -r requirements.txt

# reproduce everything (takes a few minutes on a laptop)
sh code/run_all.sh

# or run the steps one by one
cd code
python3 exp1_budget.py      # writes data/table_*.csv and data/chart_budget/alpha/... files
python3 exp2_attack.py      # writes data/chart_attack.csv
python3 exp3_correct.py     # writes data/chart_correct.csv
python3 exp4_timing.py      # writes data/chart_timing.csv
python3 check_results.py    # PASS/FAIL on the main claims
python3 plot_results.py     # writes plots/*.png
```

To reuse the formulas in your own code:

```python
import sys; sys.path.insert(0, "code")
import floodlib
help(floodlib)              # lists parameter sets and the closed-form functions
```

All random experiments use fixed seeds, so every CSV file except `chart_timing.csv` is reproduced
exactly. Timing results depend on the machine.

## Methodology

1. **Exposure model.** A decoding exposes eta = Mx + w, linear in the secret x. The variance of eta
   and a high-probability norm bound B are computed analytically (Lemma on the norm bound) and
   checked by Monte Carlo sampling (`exp1_budget.py`).
2. **Flooding and accounting.** Gaussian noise of deviation sigma is added to every exposed value.
   The Renyi divergence of order alpha between flooded transcripts with different keys is bounded and
   composed over N adaptive decodings, which gives the remaining security
   (sqrt(lambda0) - sqrt(c))^2 bits with c = N B^2 / (2 sigma^2 ln 2).
3. **Parameter selection.** Closed forms give the sigma needed for a target and the largest safe N;
   the modulus must leave room for sigma while keeping decryption correct.
4. **Validation.** A passive least-squares attack (`exp2_attack.py`) measures how many decodings are
   needed to recover the key and compares this with the information floor. Correctness and timing
   are measured in `exp3_correct.py` and `exp4_timing.py`.
5. **Baselines.** Uniform smudging, Gaussian noise with Pinsker's inequality, and Gaussian noise
   with advanced composition are computed in `floodlib.py` for comparison.
